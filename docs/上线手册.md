## 一、上线前需要负责人拍板的事

1. **上线哪一版。** 一种是已提交的版本：功能到多桌大厅（F-19），已经验证过。另一种是等策略编辑器做完、测试通过后再上。`npm.cmd run deploy` 部署的是工作区当时的文件，不管有没有提交，所以部署前先确认工作区就是想上线的那一版。
2. **网址叫什么。** Worker 名字决定 workers.dev 网址。现在还是改名前的 `probability-ember-niuniu`（“概率余烬”）。要改的话，改 `vite.config.ts` 里的 `name`，同时改 `tests/launch.test.mjs` 里对应的断言。自定义域名（P-6）也还没定。
3. **给谁看（P-2）。**
   - 如果主要读者在中国大陆：`*.workers.dev` 在大陆通常打不开。绑定自定义域名后一般能访问，但速度和稳定性没有保证，要用大陆网络实测。服务器放在大陆境内需要 ICP 备案，赌博题材（哪怕是反赌教育）在内容审核上可能有额外风险，建议先咨询再决定。
   - 港澳、新加坡和海外用户可以直接用 workers.dev 或自定义域名。
4. **公开还是小范围。** 想先只给少数人看，可以在 Cloudflare 控制台给这个 Worker 加 Cloudflare Access（访问前要邮箱验证码）。免费额度以 Cloudflare 当时的说明为准。
5. **允不允许别的网站嵌入。** 机构推广时对方可能想把页面嵌进自己的网站。现在只允许本站嵌入自己（`frame-ancestors 'self'` + `X-Frame-Options: SAMEORIGIN`）。要放开某个机构，在 `worker/index.ts` 的 `frame-ancestors` 里加上对方的域名，并删掉 `worker/index.ts` 和 `public/_headers` 里的 `X-Frame-Options`。
6. **要不要访问统计。** 现在页面没有任何统计脚本，也不写 cookie。Workers 自带的日志已开启（`observability`），只记录请求，不追踪个人。要看访客数，可以在 Cloudflare 控制台开 Web Analytics，但它会往页面里加一段第三方脚本，需要同时改 CSP（见第六节）。

## 五、出问题时回滚

列出最近的版本，然后回滚到上一个版本：

```powershell
npx.cmd wrangler deployments list
```

```powershell
npx.cmd wrangler rollback
```

`rollback` 后面不带版本号，就是回到上一个版本；带上 `deployments list` 里的版本号，就是回到指定版本。要整个下线，在 Cloudflare 控制台删除这个 Worker，或者关掉它的 workers.dev 路由。

## 六、这次做了哪些上线准备

| 文件 | 做了什么 |
|---|---|
| `worker/index.ts` | 每个请求生成一个随机 nonce，vinext 会把它标到自己的内联启动脚本上，CSP 只放行带这个 nonce 的内联脚本。所有页面响应加上 HSTS、nosniff、Referrer-Policy、Permissions-Policy、COOP 和防嵌入。删掉了模板里的图片优化和 D1 代码，它们依赖的 `IMAGES`、`DB` 绑定并不存在。开发模式（`npm run dev`）不加这些头，否则会挡住 Vite 的热更新脚本。 |
| `public/_headers` | 静态文件（`/assets/*`、图标、robots）的安全头，以及带哈希文件名的资源“永久缓存”规则。这个文件存在时，vinext 不会再自动生成缓存规则，所以缓存规则必须写在这里。 |
| `public/robots.txt`、`public/favicon.ico` | 允许搜索引擎收录；浏览器自动请求 `/favicon.ico` 时直接由静态资源返回，不再经过 Worker 渲染 404 页。 |
| `app/icon.svg`、`app/apple-icon.png`、`app/opengraph-image.png`(+`.alt.txt`) | 品牌“千”字印章图标、iOS 主屏图标、1200×630 分享卡片（一条先涨后跌、最后跌破本金线的资金曲线，示意图，不是真实数据）。删除了模板留下的四个蓝色 SVG。 |
| `app/layout.tsx` | 分享卡片的标题、描述和图片（Open Graph / Twitter），主题色。图片要用绝对地址，所以网址取自请求的 Host，换域名不用改代码。 |
| `app/not-found.tsx`、`app/error.tsx`、`app/components/status-page.tsx` | 中文 404 页和出错页，都保留“无真实货币 · 纯模拟 · 教育目的”和求助链接。原来的 404 只返回英文纯文本“Not Found”。 |
| `vite.config.ts` | 写明 Worker 名字；把兼容日期固定为 `2026-05-15`（原来是构建当天自动取，换一天构建，运行时行为可能悄悄变化）。 |
| `package.json` | 新增 `preview`、`deploy:check`、`deploy` 三个脚本，部署前强制先跑测试和 lint。 |
| `.gitignore` | 忽略 `.dev.vars*`（以后放模型 API 密钥的本地文件）和 `*.tsbuildinfo`。 |
| `tests/launch.test.mjs` | 5 项上线检查：安全头、每个内联脚本都带 nonce 且每次请求都换、分享与图标标签、中文 404 页、模板图片入口不会再报 500、静态资源规则、固定的 Worker 配置。以后谁改动了这些，`npm test` 会报出来。 |
| `design/brand/*.html` | 图标和分享卡片的源文件，重新生成方法见附录。 |

## 七、以后要注意

- **每次部署前先跑 `npm.cmd run deploy:check`。** `deploy` 脚本本身也会先跑一遍。
- **加外部资源要同步改 CSP。** 比如字体 CDN、统计脚本、从浏览器直接调用的接口。不改的话，浏览器会直接拦掉这些资源，控制台会报 CSP 错误。策略写在 `worker/index.ts` 的 `contentSecurityPolicy()` 里。
- **Phase 2 的大模型调用要走 Worker 后端。** 线上密钥用 `npx.cmd wrangler secret put <名字>` 存，本地开发放在 `.dev.vars`（已加入 `.gitignore`），绝不能写进前端代码。
- **兼容日期固定在 `2026-05-15`。** 升级 wrangler 或 `@cloudflare/vite-plugin` 时，如果想用新日期，改 `vite.config.ts` 和测试里的断言，然后重跑全部测试。本地的 wrangler 是 4.92.0，提示有新版本 4.168.0，这次没有升级。
- **模板残留（2026-11-25 已清理）。** `app/chatgpt-auth.ts`、`examples/`、`next.config.ts`、`.openai/hosting.json` 和 `build/sites-vite-plugin.ts` 已删除。`db/` 仍是未使用的 D1 模板，`tsc` 唯一的错误在 `db/index.ts`（找不到 `cloudflare:workers` 的类型）。
- wrangler 默认会发送匿名使用统计，不想发送可以执行 `npx.cmd wrangler telemetry disable`。
